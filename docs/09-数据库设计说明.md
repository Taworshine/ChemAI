## 二、MySQL 逐表讲解（每张表是干嘛的、关键字段什么意思）

### 基础数据层（dev 分支原有）

**1. sys_user —— 用户表**
系统的所有登录账号。`role` 区分三种人：`TEACHER` 老师、`STUDENT` 学生、`ADMIN` 管理员（后台专用）。
`subject` 是老师任教的学科（化学/物理…），学生为空；用它做「化学老师看不到物理内容」的数据隔离。
`class_name` 学生所在班级。密码存 SHA-256 摘要。

**2. edu_document —— 教学文档表**
老师上传的文件（课件/试卷/错题本）。`parse_status` 记录 AI 解析进度（0 待解析 → 2 成功），
`parse_result` 保存 Python AI 服务抽取出的知识点 JSON，`subject` 做学科隔离。

**3. question_bank —— 题库表**
各学科题目。`concept_name` 对齐 Neo4j 图谱里的概念名，`difficulty` 易/中/难，
APP 的「智能组卷」和「错题关联」都靠它。

**4. extraction_task / extraction_item —— 知识入库流水线（两表配合）**
老师上传文档后，AI 抽取出一批候选知识点：任务进 `extraction_task`（状态机流转），
每个候选条目进 `extraction_item`（AI 匹配到的图谱节点 + 相似度），老师逐条「采纳/修改/拒绝」，
确认后写进 Neo4j。`ingest_log` 记录每次发布/下线的操作审计。

**5. faq / faq_feedback —— 高频问答**
学生反复问的问题自动累积（`ask_count`），老师写一次官方解答（`answer`），
`publish_status` 控制是否对学生可见；学生的「有用/没用」点击存 `faq_feedback`。

**6. dialog_session / dialog_message —— AI 苏格拉底对话**
一次提问 = 一个 `dialog_session`（学生、关联题型、状态、卡点总结）；
过程里来回的每句话 = `dialog_message`（谁说的、内容、识别出的卡点类型、当前思维步骤）。

**7. practice_record —— 练习记录**
学生每次刷题的成绩单：`score/total` 得分，`detail` 是 JSON 答题明细（每题对错、我的答案）。

**8. student_profile —— 学情画像**
AI 根据学生足迹生成的笔记：`footprint` 一句话知识点（如「金属单质与强酸反应」），
`comment` 是 AI 写的讲解备注。APP「学情分析」页读的就是它。

### 移动端适配层（mobile_ 前缀，为安卓 APP 新增）

**9. mobile_meeting —— 会议表 🗓️**
一场教研会。`meeting_no` 是 6 位数字会议号（扫码加入就是扫它）；
`agenda` 议程四种：`LESSON_REVIEW` 教案评审 / `COLLECTIVE_PREP` 集体备课 /
`PROPOSITION` 命题研讨 / `PAPER_ANALYSIS` 试卷分析；
`status` 0 待开始 1 进行中 2 已结束 3 已取消；`locked` 锁定后禁止加入；
`current_doc_id` 指向当前正在评审的文档（edu_document）。

**10. mobile_meeting_member —— 会议成员表**
谁进了这场会。`role` 是 `HOST`（主持人）还是 `MEMBER`（普通成员），
`online` 记录在线状态。`(meeting_id, user_id)` 唯一，防止重复加入。

**11. mobile_annotation —— 手写批注表 ✍️（APP 核心功能）**
开会时大家在教案上画的批注。三种类型：`DRAW` 手绘圈画 / `TEXT` 文字 / `VOICE` 60 秒语音。
关键是坐标设计：`draw_data` 存**相对坐标**（0~1 的百分比），不管谁用什么尺寸的手机打开，
笔迹都能精确落在教案的同一个位置；`page` 记录第几页；`reply_to` 支持批注回复，
`is_resolved` 标记问题是否已解决。

**12. mobile_chat_message —— 会议聊天表 💬**
会中的即时消息，`msg_type` 支持 TEXT/IMAGE/FILE/SYSTEM，`reply_to` 引用别人的消息。

**13. mobile_vote / mobile_vote_record —— 投票两表 🗳️**
`mobile_vote` 定义投票：标题、类型（SINGLE 单选/MULTIPLE 多选/SCORE 打分）、
选项 JSON、是否匿名、截止时间、状态。
`mobile_vote_record` 是每个人的投票明细，`(vote_id, user_id, option_id)` 唯一防止重复投票；
SCORE 类型时 `score` 存 1~5 星。

**14. mobile_summary —— 会议纪要表 📝**
一场会一份纪要，`content` 是结构化 JSON（背景 / 讨论 / 决议 / 任务清单），
`auto_generate` 标记 AI 自动生成还是人工撰写，`is_confirmed` 主持人确认后才算正式版。

**15. mobile_task —— 会后任务表 ✅**
从纪要里拆出来的待办：`assignee_id` 负责人、`deadline` 截止时间、`status` 0 待办 1 进行中 2 已完成。
会后同步回 Web 端教学工作台。

**16. mobile_wrong_question —— 错题本表 ❌**
班级共性错题：`concept_name` 对齐 Neo4j 概念，`wrong_reason` 错因标签
（条件混淆/概念不清/计算错误/审题偏差/表达不规范），`wrong_count` 错的人数——
错的越多，教研会越该讲。支持拍照 OCR 录入（`image_path` 存原图）。

**17. mobile_plan_link —— 教案-题目关联表 🔗**
备课时把题目挂到教案上：`target_type` = WRONG（错题）或 EXERCISE（习题），
`(plan_id, target_type, target_id)` 唯一防止重复挂载。

## 三、Neo4j 图谱（4 类节点 + 关系）

| 节点 | 代表什么 | 关键属性 |
|---|---|---|
| `Concept` | 学科概念 | name（唯一）、subject、grade、keywords、description、画布坐标 x/y |
| `QuestionType` | 题型 | name、difficulty、typicalExample（典型例题） |
| `ThinkingPath` | 思维路径（解题步骤） | stepOrder（第几步）、description、hint（引导提示） |
| `Misconception` | 常见卡点 | description、frequency（出现频率） |

关系链路：**概念 —HAS_QUESTION_TYPE→ 题型 —REQUIRES_PATH→ 思维路径 —COMMON_MISCONCEPTION→ 卡点**，
概念之间用 **PREREQUISITE**（前置关系）连成学习顺序图。APP 的「教案体检」功能就是拿 AI 从教案
提取的知识点走这条链比对图谱，算出覆盖率。

## 四、这次为安卓 APP 做的数据库适配改动

1. **新增 10 张 `mobile_` 前缀的表**（上表 9~17），与 dev 原有基础表通过 `sys_user.id`、
   `edu_document.id`、`question_bank.id` 关联，老数据零迁移。
2. **坐标用相对值（0~1）**：`mobile_annotation.draw_data`，解决不同手机屏幕批注错位。
3. **一切"会议产物"都挂在 meeting_id 下**：批注/聊天/投票/纪要/任务可级联清理
   （后台管理系统删除会议时自动连带删除）。
4. **唯一约束防重**：会议号、成员、投票记录、教案-题目关联都有唯一键。
5. **注册功能**：`sys_user` 无需改结构，新增 `/api/auth/register` 接口即支持学生/教师自助注册。
6. **管理入口独立化**：新增 `/api/dbadmin/**` 管理接口（仅 ADMIN），配合独立后台管理系统
   （端口 7200，独立登录页），与教师/学生端完全分开。
7. **去脚本化**：`sql/`、`seeds/` 及所有 `.sql`/`.cypher` 文件已从项目中移除，
   数据库初始化状态只保存在 MySQL/Neo4j 实例中。
