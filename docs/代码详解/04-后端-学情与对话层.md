# 04 · 后端：学情与对话层（mind-analysis + mind-agent）

## 1. AnalysisController.java（122 行）—— `/api/analysis` 学情分析

数据源：`sys_user`（学生名单）+ `student_profile` 表（`conceptMastery` 概念掌握度 JSON、`thinkingRadar` 五维雷达 JSON，都是字符串列存 JSON）。

### `GET /students`
查 `role = 'STUDENT'` 的用户，投影成 `{studentId, username, realName, className}`。

### `GET /class/heatmap` —— 班级热力图
1. 遍历每个学生，读其 `student_profile.conceptMastery`（`{"氧化还原反应":0.85,...}`），Jackson 解析成 `概念名 → 分值` 行；
2. `LinkedHashSet` 收集出现过的所有概念名作为列（保持插入顺序）；
3. 三层循环组装 ECharts 热力图三元组 `[概念下标, 学生下标, 分值]`，缺失值补 0；
4. 返回 `{students: 显示名(学号), concepts, studentIds, data}`，前端直接喂给 ECharts heatmap。

### `GET /student/{id}/radar` —— 个体五维雷达
解析 `thinkingRadar` JSON 成 `dimensions / values` 两个数组，连同 `realName`、原始 `conceptMastery` 一起返回（前端雷达图 + 掌握度进度条共用一次请求）。

## 2. PracticeController.java（130 行）—— `/api/practice` 在线练习

### `GET /questions?subject=&count=5` —— 抽题
`SELECT * FROM question_bank WHERE subject = ?` 全量取出 → `Collections.shuffle` 洗牌 → `limit(count)`。组装结果时**只放题干字段，不放 answer**——学生抓包也看不到答案。

### `POST /submit` —— 判分归档
1. `StpUtil.getLoginIdAsLong()` 取学生身份，**不信任前端传来的 userId**；
2. 逐题：按 `questionId` 查库，用 `normalize` 归一化后比对：
   ```java
   s.replaceAll("\\s+", "")            // 去所有空白
    .replace('（','(').replace('，',',') // 全角→半角
    .replace("↑","").toLowerCase()      // 去掉化学气体符号、忽略大小写
   ```
   这个归一化让 `“Cu2+”` 和 `cu2＋` 这类书写差异不至于误判；
3. 组装明细（含用户答案、正确答案、对错）→ 一条 `practice_record` 入库（detail 列存 JSON 明细）；
4. 返回 `{score, total, details}` 给前端渲染判分结果页。

### `GET /records` —— 我的练习记录
按当前登录学生过滤、按 id 倒序。

### `GET /stats` —— 教师端看板统计
所有记录按学科分组，计算每科平均分（`score*100/total` 取整后再平均）和练习次数；另取最近 8 条记录做时间线。

## 3. AgentController.java（197 行）—— `/api/agent` AI 追问对话（SSE 流式）

实体：`dialog_session`（学生、可选题型 id、状态 0 进行中/1 已解决/2 关闭、summary 卡点总结）和 `dialog_message`（role USER/AI、内容、misconceptionType 检测到的卡点、thinkingStep 思维步号）。

### 会话管理
- `POST /session`：开新会话，自动挂当前学生 id；
- `GET /sessions` / `GET /history/{id}`：会话列表 / 按 id 升序的历史消息；
- `PUT /session/{id}/status`：更新状态（标记解决/关闭）。

### `POST /chat` —— 核心接口（SSE）
`produces = TEXT_EVENT_STREAM_VALUE` 返回 `SseEmitter`（超时 120 秒），用 `Executors.newCachedThreadPool()` 异步执行五步流水线：

```
1 存学生消息 ──→ 2 组装上下文 ──→ 3 调 Python AI ──→ 4 SSE 分块推送 ──→ 5 落库 + 总结
```

- **第 2 步 `buildContext`** 是本系统"图谱 × AI"的接合点：
  ```java
  MATCH (q:QuestionType {id: $id})-[:REQUIRES_PATH]->(p:ThinkingPath)
  RETURN p ORDER BY p.stepOrder
  ```
  从 Neo4j 拉出该题型的思维路径步骤和 hint；再查最近一条带卡点的消息、最近一条 AI 消息的 thinkingStep，拼成 `{path, hints, current_step, misconception}` 传给 Python 引擎——**AI 的每一步追问都挂在图谱的思维路径节点上**。
  另有一个细节：history **排除刚存的当前消息**（`msgs.size() - 1`），否则引擎会把首问误判为"已推进一轮"。
- **第 4 步 打字机效果**：AI 回复按 4 字符一块切片，每块 `emitter.send(event().name("message").data(chunk))`，间隔 40ms；推完再发一个 `meta` 事件（卡点类型 + 下一步序号）和 `done` 事件。前端 Chat.vue 按 SSE 事件名逐块拼字。
- **第 5 步 落库**：AI 消息入库并记下卡点/步号；一旦检测到卡点，`dialog_session.summary` 更新为"检测到卡点：XXX"——教师端会话列表和学生端错题记录都靠这个字段展示。

异常时向前端发 `error` 事件而不是让连接裸断。
