# 03 · 后端：知识层（mind-knowledge）

四个 Controller 分别对应：图谱只读、图谱管理（增删改查）、题库、教案。

---

## 1. GraphController.java（107 行）—— `/api/graph` 图谱读写

构造器注入 Neo4j `Driver`，全程手写 Cypher（没有用 Spring Data Neo4j 的 @Node 实体映射，更直接、不受旧库其他标签影响）。

### `GET /full` —— 前端图谱页的数据源
```java
session.run("MATCH (n) WHERE any(l IN labels(n) WHERE l IN ['Concept','QuestionType','ThinkingPath','Misconception']) RETURN n")
```
- 用 `any(l IN labels(n))` 限定只取本系统四类标签，**库里其他项目残留的节点不会混进来**。
- 每个节点转成 `{id: node.elementId(), label: 第一个标签, props: 全部属性}`。`elementId()` 是 Neo4j 5 的内部唯一标识（形如 `4:xxx:113`），前端连线、删除都用它定位。
- 边同理，且要求两端都必须是图谱节点，转成 `{id, type(关系类型), source, target, props}`。
- 前端 `graphRender.js` 的 `toG6Data` 消费的就是这个结构。

### `POST /node` —— 新建节点
- 先用 `label.matches("Concept|QuestionType|ThinkingPath|Misconception")` 白名单校验，防止 Cypher 注入拼接出危险标签；
- `CREATE (n:Concept $props)` 用参数化传属性（值不是拼进字符串的，安全）；
- 返回新节点的 elementId，前端立即把它画进图。

### `PUT /node/{elementId}` —— 更新节点属性
```cypher
MATCH (n) WHERE elementId(n) = $eid SET n += $props
```
`SET n += $props` 是**增量合并**：只覆盖传入的键，不动其他属性。教师拖拽节点后保存 x/y 坐标走的就是这里。

### `DELETE /node/{elementId}` —— 删除节点
`DETACH DELETE n`：先斩断该节点的所有关系再删节点，不会产生悬挂边。

## 2. GraphAdminController.java（119 行）—— `/api/graph` 管理接口

与 GraphController 同路径前缀，负责列表型管理和关系（边）操作。

### `GET /subjects` —— 学科列表
`RETURN DISTINCT n.subject ORDER BY s`，只从 Concept/QuestionType 取（路径和卡点没有学科属性，跟随上游题型）。前端两个图谱页的学科 chips 就靠它渲染。

### `GET /nodes` —— 分页搜索（知识管理页用）
- 参数：`label / subject / keyword / page / size`；
- where 条件用 `$subject IS NULL OR ...` 的写法，**一个 Cypher 同时兼容"不传=不限"和"传了=过滤"**，无需动态拼字符串；
- 计数查询 + `SKIP $skip LIMIT $limit` 分页查询各跑一次；
- 排序 `coalesce(n.id, 9999), n.name`：种子数据有数字 id 的排前面，手工建的排后面。

### `POST /edge` —— 创建关系
白名单校验关系类型必须是 `HAS_QUESTION_TYPE|REQUIRES_PATH|COMMON_MISCONCEPTION|PREREQUISITE`；按两端 elementId 找节点，`CREATE (a)-[r:类型]->(b) SET r += $props`。

### `DELETE /edge/{elementId}` —— 删除关系
`MATCH ()-[r]->() WHERE elementId(r) = $eid DELETE r`，只删关系不动节点。

## 3. QuestionBankController.java（56 行）—— `/api/question` 题库 CRUD

`QuestionBank` 实体字段：`id / subject / conceptName / questionType / content(题干) / answer(参考答案) / difficulty / createTime`，对应 MySQL `question_bank` 表。

- `GET /list`：按学科等值过滤；关键词用 `qw.and(w -> w.like("content", kw).or().like("concept_name", kw))` —— `.and()` 包住 OR 条件，避免 AND/OR 优先级 bug（否则会变成 `subject=? AND content like ? OR concept like ?`，学科过滤失效）。
- `POST` 新增：先 `setId(null)` 防止前端传值覆盖自增主键。
- `PUT /{id}` / `DELETE /{id}`：标准的按主键更新/删除。
- 注意：**这个接口返回题目是带答案的**，只给教师端用；学生抽题走 PracticeController，那边刻意不返回答案。

## 4. DocumentController.java（115 行）—— `/api/document` 教案上传与解析

`EduDocument` 实体字段：`id / title / docType(COURSEWARE 课件、EXAM 试卷、ERROR_BOOK 错题本) / filePath / parseStatus(0 待解析、1 解析中、2 成功、3 失败) / parseResult(JSON 字符串) / uploadUserId`。

### `POST /upload`
1. 取原始文件名扩展名，**文件名换成 UUID** 存盘（防重名覆盖/路径注入），落到 `app.upload-dir`（./uploads）；
2. 登记 MySQL：parseStatus=0，uploadUserId 取当前登录人；
3. 返回记录，前端刷新列表。

### `POST /parse/{id}` —— 状态机驱动的解析流程
```
parseStatus: 0 →(开始) 1 →(成功) 2
                     ↘(异常) 3
```
1. 置为 1（解析中，前端按钮此时禁用防重复点击）；
2. `extractTextLocally`：.txt/.md 直接在 Java 侧读字符串；PDF/Word 返回 null 交给 Python；
3. `aiClient.extract(...)` 调 Python 服务（内部会用 pdfplumber/python-docx 抽文本，再由 DeepSeek/规则引擎抽知识点）；
4. 成功：结果 JSON 序列化存 `parseResult`，状态 2；失败：状态 3 并返回错误信息。

**Java 与 Python 同机部署是这个设计的前提**——传的是本地文件路径，不是文件流。
