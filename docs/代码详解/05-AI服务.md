# 05 · AI 服务（ai-service，FastAPI，端口 8000）

## 1. main.py（22 行）—— 入口

```python
app = FastAPI(title="Mind Empower AI Service", version="1.0.0")
app.include_router(extract.router)
app.include_router(chat.router)
```

- 挂载两个路由模块 + 一个 `/api/health` 健康检查（返回 `{ok, llm_enabled}`，`llm_enabled` 反映是否配置了 DeepSeek Key——Java 端 `AiServiceClient.health()` 探的就是它）。
- `if __name__ == "__main__"` 里用 uvicorn 启动；实际部署由命令 `uvicorn main:app --port 8000` 启动。

## 2. services/parser.py（26 行）—— 文档转文本

`parse_file(file_path)` 按扩展名分派：
- `.pdf` → pdfplumber 逐页 `extract_text()` 拼全文；
- `.docx/.doc` → python-docx 逐段落拼文本；
- 其他 → 按 UTF-8（errors=ignore）当纯文本读。
文件不存在返回空串（路由层会据此返回"未提取到文本"错误）。

## 3. routers/extract.py（30 行）—— `/api/extract` 知识抽取

```python
text = req.text or parse_file(req.file_path)   # 优先用 Java 已抽好的文本
result = llm.extract_knowledge(text)
result["doc_id"] = req.doc_id
result["ok"] = True
result["engine"] = "deepseek" or "rule-based"  # 告诉调用方这次用的是哪套引擎
```
返回结构固定为 `{concepts, question_types, thinking_paths, misconceptions}`。

## 4. routers/chat.py（36 行）—— `/api/chat` 追问生成

用 pydantic 模型做入参校验（`ChatRequest{message, history[], context}`），把模型转成 dict 后交给 `llm.socratic_reply`，回复包上 `ok` 和 `engine` 返回。本身没有逻辑，是一个"参数校验壳"。

## 5. services/llm.py（279 行）—— 全系统最聪明的部分

两个引擎，优先 LLM、失败降级规则：

### DeepSeek 通道
```python
USE_LLM = bool(os.getenv("DEEPSEEK_API_KEY"))
def chat_completion(prompt):
    if not USE_LLM: return None
    ...OpenAI SDK 调 deepseek-chat，temperature=0.5, max_tokens=300...
    任何异常都返回 None → 交给规则引擎
```

### `socratic_reply` —— LLM 优先的追问
把思维路径、当前步号、历史卡点组装成中文 prompt，明确五条约束：禁止给答案、只提问引导、停滞 2 次才给提示、≤80 字、亲切鼓励。DeepSeek 成功则裁剪到 90 字返回；否则进 `rule_reply`。

### `rule_reply` —— 无 Key 时的规则引导引擎
**这是"离线也能演示 AI 追问"的关键。** 流程：

1. `_classify` 给学生的消息分类：
   - 命中 `GIVE_UP` 词表（"直接告诉我""放弃"…）→ `giveup`；
   - 命中 `STUCK` 词表（"不知道""没思路"…）→ `stuck`；
   - 短回复（≤6 字、无数字、无推进词）且上两轮也停滞 → `stuck`；
   - 含推进词/数字/长分析（≥15 字）→ `progress`；
   - 否则 `neutral`。首轮提问强制不算 progress（防止跳过第一步）。
2. 按状态分流：
   - **giveup**：`REFUSE_ANSWER` 温柔拒绝 + 拉回当前步骤的探问；
   - **stuck**：上一次也 stuck → 给出该步骤的 `hint` 并标记卡点 `CONCEPT_UNCLEAR`；否则先鼓励再探问；
   - **progress**：`_echo_fragment` 用正则从学生回答里抓化学式/数值（如 `Cu(NO3)2`、`22.4L`）做复述式肯定（"你提到 CuO，…"），进入下一步并附下一步 hint；已到末步则 `_finish` 让学生自己总结整条路径；
   - **neutral**：当前步骤换个角度继续问（50% 概率附 hint）。
3. 追问去重：`_recent_questions` 收集本会话已发出的追问，`_ask_step` 优先选没用过的探问模板。
4. 所有回复裁剪到 ≤110 字。

### `_subject_fallback` —— 没有思维路径时的学科级降级
`SUBJECT_RULES` 是一张 **9 学科关键词 → 启发式问题 → 卡点类型** 的对照表（数学"先画个图或写个式子"、历史"从政治经济思想几个维度想"…），匹配不到就轮转鼓励语 + 默认问题。这套表也就是之前"多学科追问规则"的落地。

### `extract_knowledge` —— 教案抽取
优先让 DeepSeek 输出严格 JSON（正则 `\{.*\}` 提取后 `json.loads` 校验，concepts 非空才采用）；无 Key 时降级为**内置概念词表在文本中做匹配**（命中前 6 个），兜底返回一组默认结构，并打上 `engine: rule-based` 标记。

**设计思想**：无论有没有配 DeepSeek Key，对外接口的形状永远一致，`ok` 永远为 true（除非连文本都抽不出来），上层 Java 永远拿到可展示的合法结果。
