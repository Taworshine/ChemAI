# 教师上传 → 大模型抽取 → 教师确认 → 知识图谱 设计方案

> 版本：v1.4（2026-10-26） · 状态：**P1 + P2 + P3 + P4 + P5（语义归并/待办徽标）已实现并全流程验证通过**
> 目标：教师上传 讲义 / 教案 / 知识点 → 大模型抽取 → **教师中途确认** → 写入 Neo4j 知识图谱；
> "机器预匹配 + 教师裁决"防节点重复；确认流程**不展示图谱**（表格化）；
> 落地 教师端「教研」与学生端「高频问题」，并让学情数据**回流反哺备课**，形成业务闭环。

---

## 〇、业务全景闭环（一张图看懂整个业务）

```
【备】教师备课产出          【建】资产化入库            【审】人工把关
教案 / 讲义 / 知识点  →  解析 → 抽取 → 预匹配  →  教师确认（合并/新建/忽略）
                                                   │
【研】教研洞察              【用】学生使用              【发】发布上线
缺口清单/卡点报告   ←  学情聚合(卡点/高频问题)  ←  练习 · 智能追问 · 高频问题
        │                                          ↑
        └──────────── 指导下一轮备课 ←───────────────┘
```

四个角色在各环节的位置：

| 环节 | 教师 | 教研组长（可选） | 学生 | 系统 |
|---|---|---|---|---|
| 上传 | 上传、选类型、命名 | — | — | 解析预检 |
| 抽取/匹配 | — | — | — | 大模型抽取 + 去重预匹配 |
| 确认 | **逐条裁决**、编辑、手动补漏 | 可二审抽查 | — | 落待确认表 |
| 发布 | 一键发布 / 下线 | 审核（可选） | — | 版本递增 |
| 使用 | 查看学情 | — | 练习、追问、看高频问题 | 追问命中优先级 |
| 回流 | 高频问题解答、卡点教研 | 教研报告 | 反馈"有用/无用" | 聚合统计、生成缺口清单 |

**核心原则**：大模型只提候选，教师点头的才进图谱；学生只用"已发布"的内容；学情数据必须能回流成教研洞察，反哺下一轮上传。

## 一、上传规范（三种类型 + 命名与字典）

### 1. 三种类型

| 类型 | 适用内容 | 支持格式 | 抽取目标 |
|---|---|---|---|
| A · 教案 | 教学目标/重难点/教学过程 | .docx / .pdf / .md / .txt | 概念+题型+思维路径+卡点 |
| B · 讲义 | 知识点讲解 + 例题解析 | .docx / .pdf / .md / .txt | 同上 |
| C · 纯知识点 | 零散知识点批量录入 | 在线粘贴 **或** 模板 Excel/CSV | 仅概念（+可选前置关系） |

统一约束：单文件 ≤ 20MB；C 类提供**模板下载**（列见下）；上传页为三 Tab。

### 2. 文件命名规范（建议格式，前端做校验提示）

```
学科_年级_课题_作者_日期.扩展名      例：化学_高一_氧化还原反应_王老师_20261026.docx
```

### 3. 数据字典（统一维护，防脏数据）

- **学科字典**：语文/数学/英语/物理/化学/生物/历史/地理/政治（下拉选择，不允许自由输入）；
- **年级字典**：高一/高二/高三；
- **概念命名规范**：以教材通用名为准，不带"（必修一）"等版本后缀（版本信息放属性）。

## 二、任务状态机（extraction_task 生命周期）

```
CREATED ──→ PARSING ──→ EXTRACTING ──→ MATCHING ──→ PENDING_CONFIRM
                                                    │        │
                                          （教师确认+提交） │
                                                    ▼        ▼
                                              WRITING ──→ PUBLISHED ──→ OFFLINE（下线，数据保留）
                                                                 │
                                                    任意环节 ──→ FAILED（可重试，保留现场）
                                                    PENDING_CONFIRM ──→ CANCELLED（教师放弃）
```

要点：
- 状态全程可见，教师端上传管理列表用状态标签展示；
- `PENDING_CONFIRM` 支持**草稿保存**，教师可分多次确认，不丢进度；
- `PUBLISHED/OFFLINE` 控制**学生端可见性**：写入 Neo4j 不等于上线，发布后学生才能练习/追问用到。

## 三、大模型抽取 Schema（带置信度与原文溯源）

### A/B 类（教案、讲义）
```json
{
  "concepts":       [{"name":"","subject":"","grade":"","description":"",
                      "keywords":[],"confidence":0.0,"quote":"原文摘录≤100字"}],
  "question_types": [{"name":"","subject":"","difficulty":"","typical_example":"",
                      "confidence":0.0,"quote":""}],
  "thinking_paths": [{"question_type":"","steps":[{"order":1,"description":"","hint":""}],
                      "confidence":0.0}],
  "misconceptions": [{"description":"","related_concept":"","frequency":"high|mid|low",
                      "confidence":0.0,"quote":""}]
}
```

### C 类（纯知识点）
```json
{
  "concepts": [{"name":"","subject":"","grade":"","description":"","keywords":[],
                "prerequisites":["已有概念名（可空）"],"confidence":0.0,"quote":""}]
}
```

增强点：
- **confidence**：大模型对每条结果自评置信度（0~1）；`<0.6` 的条目在确认页自动置顶并标橙"重点核对"；
- **quote**：原文摘录，教师可对照原文判断抽得对不对；
- 无 Key 时沿用现有关键词降级抽取（confidence 统一标 0.3，全部进入人工核对）。

## 四、去重预匹配（防重复的核心）

候选节点 vs Neo4j 现有节点（**匹配范围 = Concept / QuestionType / ThinkingPath / Misconception + 化学本体 Entity**，你库里的本体也参与防重）：

| 级别 | 规则 | 标记 |
|---|---|---|
| L1 精确 | name 相同 + 学科相同 | 「已存在·建议合并」 |
| L2 模糊 | 名称互相包含 / 编辑距离 ≤2 / 关键词 Jaccard ≥0.5 | 「疑似重复」附相似度分数与已有节点信息 |
| L3 语义 | （可选增强）大模型判断 same / child-of / different | 作为教师裁决的参考建议 |

教师裁决三选一，语义更细：
- **合并（同义）**：不建新点，抽取的描述/关键词补充进已有节点，记来源；
- **建关系（上下位）**：不建新点，候选作为已有概念的前置/相关（PREREQUISITE）；
- **新建**：确认是不同概念。

阈值（编辑距离、Jaccard）做成**配置项**，初期宽松宁可多给教师看，不可漏重。

## 五、教师确认页（不展示图谱）

布局（从上到下）：**汇总条**（X 新建 / Y 合并 / Z 忽略 / W 待裁决，未裁决完不能提交）→ 四个分组卡片：

1. **疑似重复**（优先展示）：左候选右已有节点（名称/学科/描述/相似度/LLM建议），单选 合并·建关系·新建；
2. **新增节点**：行内编辑名称/学科/年级/描述/关键词，confidence<0.6 标橙；
3. **思维路径**：步骤拖拽排序、增删步、编辑 hint；可挂到某个已确认题型；
4. **题型与卡点**：同新增节点，典型例题可预览。

能力：
- 「全部接受建议」快捷键 + 提交前二次确认汇总；
- **手动补漏**：确认页可直接手动添加抽取漏掉的知识点（走同一套去重校验）；
- **忽略/删除**：抽取噪音标记忽略，不写入；
- 草稿自动保存；乐观锁防两位教师同时处理同一任务（后者只读）。

## 六、写入 Neo4j 与发布/版本/回滚

```cypher
MERGE (c:Concept {name:$name, subject:$subject})
SET c.description = coalesce($description, c.description),
    c.keywords    = coalesce($keywords, c.keywords),
    c.source_doc_id = $docId, c.created_by = $teacherId,
    c.created_at = datetime(), c.version = $version
```

- **MERGE 幂等**：重复提交、重复上传不产生重复节点；
- **溯源**：节点/关系带 `source_doc_id / created_by / created_at / version`，可从节点反查出自哪份教案；
- **ingest_log**：每次提交记录明细（新建/合并/忽略清单 + Cypher 批次号），**支持按任务回滚**（删除该任务新增的节点与关系，合并补充的属性可还原）；
- **发布**：写入后默认学生不可见；教师点「发布」版本 +1，学生端接口只查 `version ≤ 当前发布版`；「下线」即时对学生隐藏但数据保留。

## 七、学生端「高频问题」业务细化

1. **聚合规则**：按 题型/概念 分组统计提问次数；同义提问由 LLM 语义聚类归并（P5 已实现，含基准选择/解答继承/反馈迁移）；排序 = 提问人数 × 时间衰减（近 30 天权重高）；
2. **页面**：高频榜（问题摘要 + 提问人数 + 趋势箭头），展开看**官方解答**（折叠）；无官方解答显示"教师解答中"；
3. **互动**：「我也有这个疑问」→ 一键跳转到智能追问并自动带上该问题上下文；解答下可点**有用/无用**；
4. **追问命中优先级**（改造现有 AgentController）：提问先查 faq 库（概念/题型匹配）→ 命中则先展示标准解答 + 问"还有哪里不清楚？"，未命中或学生继续追问才走思维路径引导；
5. **通知**：关注的问题有了官方解答，学生端小红点提醒。

## 八、教师端「教研」业务细化

1. **上传管理**：历史列表（状态标签/类型/写入统计/可回滚/可下线）；
2. **待确认中心**：未完成任务（中断可续）；
3. **图谱资产看板**：节点/关系总量与增长趋势（近 30 天曲线）、学科覆盖雷达图、来源分布（哪份教案贡献了多少）；
4. **卡点教研**（强化现有学情分析）：班级/题型/时间三维聚合，输出教研建议（如"3 班'化学平衡'卡点集中，建议回补前置概念'化学计量'）；
5. **高频问题工作台**：待解答队列 → 撰写/挂接标准解答 → 观察效果（命中率、有用率、仍追问率）；
6. **缺口反哺（闭环关键）**：学生高频问、但知识图谱里**没有对应概念**的问题，自动生成「待补充知识点」清单，教师可**一键转为 C 类上传任务**——学生的问题直接变成下一轮的备课输入。

## 九、通知、审计与安全

- **站内通知**：解析完成待确认、回滚失败、自己解答的问题被大量查看等；
- **审计日志**：确认页的每次编辑/裁决、发布/下线、回滚全部留痕（谁、何时、改了什么）；
- **权限**：确认/发布只能本人或教研组长；学生只读；接口全部走现有 sa-token 鉴权；
- **安全**：上传文件类型/大小白名单校验；Cypher 全参数化（沿用现有写法，禁止字符串拼接值）；LLM 调用超时/限流自动降级规则抽取，任务可重试。

## 十、页面结构速览（文字草图）

- **教师端-上传页**：三 Tab（教案/讲义/知识点）｜拖拽上传区 + 命名规范提示 + 模板下载｜上传后跳「任务详情」看状态机进度条；
- **教师端-确认中心**：左侧任务列表（状态筛选），右侧确认工作区（第五章布局）；
- **教师端-教研看板**：顶部 4 个指标卡（节点总数/本月新增/待确认/待解答）｜增长曲线 + 学科雷达｜卡点 Top5 班级榜｜缺口清单（一键转上传）；
- **学生端-高频问题**：搜索框 + 学科筛选 chip｜榜单卡片（问题/人数/趋势/解答折叠）｜"我也有疑问"入口。

### P4 验证记录（2026-10-26）

- **回滚**：教案任务提交入库（4 概念 + 2 题型 + 3 路径 + 2 误区 = 11 个新建节点，elementId 清单落库 extraction_task.created_node_ids）→ 回滚 11/11 精确删除 → 任务 6 已发布节点、种子节点全部完好；旧任务（无清单）回滚被安全拒绝；ingest_log 留有 SUBMIT/ROLLBACK 审计链。
- **溯源**：教师/学生端图谱点击节点均显示来源（学生端：「📄 盐类水解知识点 · 王老师 提供」；种子节点显示「系统预置知识点」；教师端额外显示入库时间/任务状态/一跳关系摘要）。
- **安全设计**：溯源属性改为 ON CREATE SET 写入——命中已有节点只补内容不抢注出处；回滚按 elementId 清单 + source_task_id 双重校验删除，从机制上杜绝误删种子/本体节点。

### 验证记录（2026-10-26）

- C 类（纯知识点文本）→ kimi-k2.6 抽出 3 条概念，L2 命中已有「水解」节点（相似度 0.8），教师批量裁决「新建」→ 提交入库 → 3 个 Concept 以 DRAFT 写入 Neo4j → 发布转 PUBLISHED → 学生端图谱可见（总节点 83→86）。
- A 类（教案文件）→ 抽出 4 概念 + 2 题型 + 1 思维路径(含 steps) + 2 误区，全部完成与已有图谱节点的预匹配。
- 高频问题：15 条学生真实提问自动聚合；教师发布「离子方程式书写」标准解答后，学生相似提问（2-gram Jaccard ≥ 0.35）直接命中标准解答，ask_count 自动累加。
- 关键坑位记录：reasoning 模型（kimi-k2.6）会先把 token 花在思考上，max_tokens 必须给足（抽取 8000 / 对话 2000 / **聚类 8000**），否则 content 为空静默降级。

### P5 验证记录（2026-10-26）

- **语义归并**：教师端点「智能归并相似问题」→ 后端取 ask_count Top50 → kimi-k2.6 语义聚类（约 107s，免费档 org 并发=1 所致，换付费 Key 会显著加快）→ 正确归并「Ba(OH)2和H2SO4反应的离子方程式怎么写 / …到底怎么书写啊」两条；基准保留了**已发布且有解答**的一条（ask_count 累加、解答与发布状态无损），冗余行删除，无反馈数据损失。
- **失败安全**：LLM 聚类接口不可用时（ok=false）后端**零数据改动**直接报错，前端提示重试；归并操作前端有二次确认弹窗（聚并不可逆）。
- **待办徽标**：侧边栏「教研中心」显示待确认任务+待解答问题合计徽标，「确认中心」「问题解答」子项各自徽标，60 秒轮询；徽标为 0 时不显示。
- **问题解答工作台**：统计卡（待解答/已发布/总数）与库一致，列表含热度/反馈/状态，「写解答」对话框渲染正常（未做实际保存，避免污染数据）。
